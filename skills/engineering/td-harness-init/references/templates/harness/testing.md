# 测试规范（testing）

> **walkinglabs L10**：E2E 不只是验证手段，会反向重塑 AI 编码行为。
> AI 知道要过 E2E 时会写出本质更好的代码。

## 测试金字塔

```
        E2E (Playwright / 真实环境)        ← 完成定义
        ↑
        集成 / 契约测试                     ← 后端首选
        ↑
        单元测试                           ← 边界细节
```

## 完成定义

满足以下全部才算完成：
1. 单元测试覆盖率不降低
2. `make e2e` 退出码 0
3. 后端：契约测试通过 + 影子流量比对无差异
4. PROGRESS.md 标记 `[x]`
5. failures.md 沉淀（如有踩坑）

## E2E 在不同形态项目的落地

| 项目类型 | E2E 形态 | 工具示例 |
|---------|---------|---------|
| 前端 / 全栈 | 浏览器自动化 | Playwright / Cypress |
| 后端 API | 契约测试 + 服务级集成 | Pact / Schemathesis |
| 后端服务 | 影子流量 + 重放 | 自建 / Diffy |
| 库 | 端到端使用场景 | 真实小项目跑通 |

后端 E2E 难，但**解法不是降级到单测**，而是契约测试 + 影子流量（圆桌 2 Dijkstra 让步）。

## 重构场景：黄金样本（输入-输出快照）

重构的目标是行为不变。Beck 的 Red-Green-Refactor 在重构上不直接适用——这时使用「黄金样本」：

```
testdata/
├── case-01/
│   ├── input.json      # 固定输入
│   └── expected.json   # 期望输出（在重构前生成）
└── case-02/...
```

重构过程中，所有黄金样本必须通过；不通过即说明行为变了。

## 反模式

- ❌ 只跑单元测试就声称完成（lecture-10 的"组件边界盲视"）
- ❌ AI 修改测试断言让自己通过（pre-commit hook 应阻断）
- ❌ E2E 难做就降级到单测
- ❌ 黄金样本在重构后才生成（已被污染）
