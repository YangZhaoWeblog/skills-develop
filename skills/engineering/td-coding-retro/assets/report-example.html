1. 提交后补写编号，导致反复补提交

Agent 提交代码后，又按要求把提交编号写进任务记录。记录因此再次出现未提交的修改，需要再提交一次。最后已经处理完毕。

改进方案

下次在提交前完成任务记录，提交后直接向你报告结果。

这次问题出在派发与执行环节。 现有提交规则已经要求这样做，因此不需要新增规则。

实施结果

经独立 Agent 验证，本项改进有效：减少了重复提交，且没有遗漏结果报告，已保留。

3. 测试通过，还要检查它证明了什么

改进方案

可区分的执行数据，才能让断言发现输出串线。 无需为此增加验证规则；这个案例可用于解释已有验证规范。

实施结果

经独立 Agent 核对，本项改进尚未证实有效：没有取得新测试能识别输出串线的证据，已回退。

测试使用替身，且需要证明多个执行互不干扰。

反例

所有执行返回相同标识和文本，断言无法区分结果来源。

正向做法（以证据状态为准）

后续补上可区分的执行数据与不串线断言，再独立复验。
