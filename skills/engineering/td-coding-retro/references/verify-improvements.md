# 改进效果验证

用户选定报告事项后使用。目标是检验改动是否改善预期行为，并据此决定保留或回退。

## 实施前

逐项记录报告身份与编号、问题证据、改动位置、预期改善、通过标准、必须保留的行为、验证方法和回退范围。简单改动可以用几行记录，不另建整套任务模板；目标项目已有任务记录时沿用。

标准在实施前确定，描述可观察的结果。例如：复现“提交后又改任务记录”的场景时，Agent 应在提交前完成记录，提交后无需再改受跟踪文件；同时仍能交代实际提交结果。不能把“新增一条规则”作为效果标准。

证据是否充分，以预定标准、必要约束和本次宣称的效果范围判断。隔离场景已满足全部标准时，可报告该场景验证通过；只有具体未覆盖风险会影响结论时才补充验证。生产观察、长期跟踪和跨项目泛化按本项需要选择，不能为追求完整而事后增加门槛。恢复时发现标准是事后补定的，记录这一事实，并说明判断依据。

保留涉及文件的改前副本或可定位版本，以及本次差异。回退只撤销本项改动，保留用户和其他任务的修改；重叠而无法安全拆开时报告具体冲突。多项改动有依赖时预先说明联合验证与回退范围，授权仍按用户选定事项核对。

在看到验证结果前区分两种性质，并写明依据：

- **实验性改进**：待验证收益的提示、组织方式、规则或流程调整。
- **必要修正**：恢复已批准要求、修复已证实缺陷或满足明确安全约束。不能只因作者偏好标为必要。

## 独立验证

使用新上下文中的独立 Agent；切换作者口吻不算独立。给它选定事项、必要原始证据、预先确定的标准、改前版本、实际差异及相关项目材料；提供检查所需事实，不提供作者的成功判断。记录实际调用或会话标识、所检版本、方法、原始结果和结论，支持后续核对。

选择足以检验预期行为的方法。复现原问题情境，并加入能暴露误用或副作用的场景；以实际输出、执行轨迹或可核对的产物判断。仅阅读新规则后说“看起来合理”，属于审查，不能证明行为已经改善。确定性缺陷可以用针对性检查直接验证；文本表达改善可以检查独立读者的理解和后续操作。

需要比较效果时，可选 A/B：新旧版本使用相同原始任务材料和初始条件，在互不继承历史的上下文中运行；控制模型、工具和资源等条件，并记录无法控制的差异。用于设计的样例与新增验证样例分开记录；旧样例复测只能支持回归结论，不能证明泛化效果。存在明显随机性时增加独立运行，不把一次有利输出当作稳定收益。

需要降低评审偏见时，隐藏候选来源和新旧身份、随机排列输出，再由独立评审按既定标准判断。若生成者也不知道版本身份，才称双盲；实际只能做到评审盲测时如实命名。A/B 和盲评均为可选方法，选用理由取决于本项验证需要。

验证环境遵循目标项目的权限和分工；可使用隔离副本、模拟场景或获准的检查命令。独立上下文不等于环境隔离，不因此授权访问生产、修改真实数据或执行外部操作。

## 决定保留还是回退

| 结果 | 处理 |
| --- | --- |
| 达到通过标准，必要约束未退步 | 保留，说明具体改善及证据适用范围 |
| 未改善或造成退步 | 撤销本项实现，核对回退结果；必要要求仍需满足，范围内可修复复验，不能恢复已知缺陷后声称完成 |
| 证据不足 | 针对缺口补充验证；仍不足时，实验性改进回退，必要修正保留并明确已验证部分及剩余不确定性 |

每项至多先补充一轮针对性验证或范围内修复；仍无结论或仍失败时按表处理并汇报。需要扩大范围、降低标准、额外权限或改换方案时交用户决定。标准确需改变时说明原因，按目标规则确认后重新验证。

缺少独立 Agent、原始记录或必要运行条件，都属于验证未完成，不能宣称有效。必要修正的保留不等于验证通过；存在已证实退步时不能以“必要”为由保留失败实现。

## 汇报

用户选定的每个编号都有结果：已改进并保留、已回退、必要修正已保留但验证未完成，或因具体冲突无法安全处理。各用一句话说明依据，详细轨迹按需查阅。不得把所有“文件已改完”统一报成“改进有效”；全部选定事项处理后，再交用户选择是否尝试其他方案。

更新原 HTML 报告前保留副本，读取现有内容和用户修改。保持原编号、发现、提案及历史处理状态，在选定事项的详情内补“实施结果”，先明确验证方法和有效性结论，再说具体效果与处理结果。例如：“经独立 Agent 验证，本项改进有效：减少了重复提交，且没有遗漏结果报告，已保留。”实际使用 A/B 或盲评时写对应方法，没有执行的方法不能列入；验证未完成时直接说明缺什么证据。完整调用标识、所检版本、原始结果与回退核对记录放到底部折叠区；记录本轮处理时间，保留原会话日期。无结果的事项不添加占位说明。

结果句按“验证方法，本项改进有效／无效／尚未证实有效：具体效果或缺口，处理状态。”组织，先给结论，再解释。必要修正因环境缺失而未验证时用第三种。引用已有独立验证记录时可以写“根据已有独立 Agent 验证记录”，不能把他人执行写成本轮重跑。只读评审中拟写的“已保留／已回退”属于操作完成后的文案，实际处置未完成前标为待执行，不能直接发布为完成结果。

保留项说明“哪些证据支持在什么范围内有效，因此保留”，必要修正证据未全时明确尚待验证。回退项区分“测试发现无改善或退步”与“证据不足、尚未证实有效”，分别交代原因；不能把证据不足写成已证明无效，也不能把预设样例中的有效前提当成本轮实验发现。正文沿用既有样式，开头验证方法与有效性结论、具体效果都用正常字重，仅句末“已保留／已回退／验证未完成”用 strong 加粗。标题只写“实施结果”，不另加标签、色块或徽章。

同步顶部结论与页尾选择状态，使已完成、已回退和待处理事项准确对应；结果混合时逐项说明，不把已回退的事项计为已改进。保留模板样式和交互，重新检查切换与折叠。终端仅通知“第 1、3 项已改进，第 5 项已回退”及报告路径；存在未完成验证或冲突时同时简短点明。用户明确只需终端汇报时遵从。
