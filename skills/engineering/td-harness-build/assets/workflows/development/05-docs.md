# 05. Docs

> **执行角色**：Executor；派发与权限见 **.harness/agent-roles.md**。
> **用途**：同步本次改动影响的文档，记录更新内容与核对结果。
> **填写范围**：仅记录文档影响、文档改动、一致性核对及完成情况。不得新增章节或写入其他执行过程；核验和审阅结果链接对应记录。
>
> **方法**：对照最终代码及 **02-plan.md、03-implement.md、04-verify.md**，增量更新相关文档；无长期事实变化时，记录“不涉及”及原因。

## 1. 文档影响检查

按清单核对本次文档影响，通过 **AGENTS.md 的 Index** 定位文档，并确认 **.harness/docs/** 中的实际路径；其他文档按项目实际位置检查。不涉及的项注明原因。

逐项核对受影响文档，避免只改代码，或只改一份文档而遗漏相关说明。

| 核对项 | 何时检查 | 文件 |
|---|---|---|
| ⬜ **系统架构** | 模块、调用链或并发模型变化 | .harness/docs/architecture.md |
| ⬜ **上下游关系** | 依赖或拓扑变化 | .harness/docs/dependencies.md |
| ⬜ **使用流程与业务规则** | 用户操作或业务行为变化 | .harness/docs/product-state/user-flows.md、business-rules.md |
| ⬜ **产品全景** | 产品现状子文档变化 | .harness/docs/product-state/product-map.md |
| ⬜ **接口契约** | 接口或字段变化 | 项目实际 proto / IDL / OpenAPI / 路由定义及注释 |
| ⬜ **接口索引** | 契约路径、service 或路由变化 | .harness/docs/contracts/index.md |
| ⬜ **字段与接口变更历史** | 字段或接口语义变化 | .harness/docs/contracts/change-history.md |
| ⬜ **数据库说明** | 数据库用途、关系、约束或文档链接变化 | .harness/docs/data/database.md |
| ⬜ **单元测试规范** | 测试约定、命名或 Mock 策略变化 | .harness/docs/testing/unit-tests.md |
| ⬜ **本地环境与开发** | 环境、配置、启动或调试方式变化 | .harness/docs/devops/local-dev.md |
| ⬜ **发布与恢复** | 发布、检查或恢复方式变化 | .harness/docs/devops/release.md |
| ⬜ **用户说明** | 用户可见的变化 | 对外 README / 用户指南，按实际路径填写 |
| ⬜ **版本变更日志** | 项目版本记录约定要求更新时 | CHANGELOG，按实际路径填写 |

产品现状须核对来源与时间，全景图与子文档保持一致、链接有效；改图后检查渲染，未核实内容标明“待核实”。未实现计划不写成现状，已结束的需求和开发任务记录不续改。

接口变更历史保留变更前后、原因、兼容性影响与依据，不覆盖已有记录。接口说明站在调用者视角，说明做什么、怎么调用、返回什么、错误如何处理；字段定义引用契约，不重复维护字段表。

> eg:（反例）新增字段后只改代码，或只改契约，却遗漏接口索引、字段变更历史及受影响的调用链说明。

## 2. 改动明细

写明具体变化及影响，不用笼统结论代替改动说明。

> eg:（反例）只写“修复 bug”或“优化性能”，读者无法知道行为发生了什么变化。

| 文档 | 路径 | 改动类型 | 改动说明 | 状态 |
|------|------|---------|---------|------|
|  |  | 新增 / 修改 |  | ⬜ |

> 状态：⬜ 待更新 \| ✅ 已更新 \| ➖ 不涉及

按本次文档变化核对关键说明与最终代码、契约或配置是否一致，保留具体依据；不只检查链接有效，也不在本文件复制字段定义。

| 核对项 | 对应代码／契约 | 核对结果 |
|---|---|---|
|  |  |  |

> eg:（示例）文档说明“参数嵌套最多 6 层”；对照实现中的深度上限及判断逻辑，记录一致或具体差异。
