# 06. Review — 独立验收

> **执行角色**：Reviewer；派发与权限见 **.harness/agents.md**。
> **用途**：独立核对最终改动、需求与验收条件（Acceptance Criteria，AC）及验证证据，记录审阅发现、处置和用户确认。
>
> **方法**：按 **.harness/docs/code-review.md** 审阅，读取 **04-verify.md** 的验证结果；作者自检不替代独立审阅，不默认重跑全部验证，不复制长期检查清单。

需求与 AC 从 **00-overview.md §3「需求与验收入口」** 读取；方案、验证和文档更新分别见 **02-plan.md、04-verify.md、05-docs.md**。

## 2. 作者交接

只摘要本次审阅重点，详细记录引用对应章节。

- **范围与重点**：本次改动边界、需要特别核对的实现或项目规则。
- **验证与缺口**：引用 **04-verify.md** 的结论，说明未验证项及原因。
- **文档与风险**：引用 **05-docs.md** 的更新记录，说明剩余风险。

按 **.harness/docs/code-review.md** 判断问题及严重度。每项写明具体位置和需求、规则或风险依据；未发现问题时写“无”。

**不因工具通过就忽略分层错误或无效断言，也不凭“太长”“更优雅”阻断。** 不采纳或批准例外的理由记入 **§4「讨论与决议」**；修复项填写复验／复审依据。

## 5. 复盘

检查本轮是否出现值得记录的失败；判断范围及复盘方法见 **.harness/docs/failures.md**。详细复盘写入该文件，本节只记录结论与链接。

- **复盘结论**：无重要失败／已记录。
- **失败记录链接**：

提出改进建议不代表已经实施。修改 Harness 须在已有授权范围内；超出范围时，按 **AGENTS.md §2.6「用户确认」** 处理。
