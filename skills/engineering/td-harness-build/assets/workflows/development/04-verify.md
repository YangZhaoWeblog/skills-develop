# 04. Verify — 检查

> **执行角色**：Verifier；派发与权限见 **.harness/agents.md**。
> **用途**：验证当前实现是否满足已批准的 Plan 与验收条件（Acceptance Criteria，AC），记录实际结果、失败问题与复验结论。
>
> **方法**：按 **02-plan.md §6.4** 执行检查，按 **02-plan.md §6.1** 验证 AC；检查标准与处理规则见 **.harness/docs/verification.md**。

AC 包含 UI 交互要求时，**必须实际操作界面**，不能仅用 API 测试替代。

验收通过须有**实际执行证据**；读取或解析 Gherkin、查看原型不能算通过。

按 **02-plan.md §6.4** 执行变异测试（Mutation Testing）：工具故意修改代码，检查测试能否发现行为变化。

**逐项核对结果**，不能只看退出码或总百分比。

+ **结果统计**：沿用工具分类填写数量，未提供的数据写“未提供”。 

eg:（示例，填写时替换）测试发现 8 项；仍通过（存活）2 项；未覆盖 1 项；执行错误 1 项。

|---|---|---|---|
|  |  | 存活／未覆盖／未执行／执行错误／其他 |  |

等价变异是代码变化但行为不变。**排除等价项须给出具体依据并独立核验**，不能仅凭“测试仍通过”判为等价。  
在上表“变异结果”列注明等价结论，在“相关测试、问题或等价依据”列填写理由与独立核验记录；原始统计数量不变。

**保留首次结果**，修正与复验记录在 **§7**；不把原因不明的测试失败或执行错误算作“测试已发现”。

执行与缓存处理按项目规范，不手改工具清单来隐藏问题。
