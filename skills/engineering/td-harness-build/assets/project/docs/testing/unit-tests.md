## 二、测试编写规范

### 1. 行为与断言

按 **[tdd.md](tdd.md)** 逐行为执行 **Red → Green**；用例设计在当前 **02-plan.md**，结果在 **04-verify.md**。只在出现明确坏味道或规范违规时做必要重构，遵守批准范围。

测试预期依据需求、契约或独立推导，不照抄实现结果。按行为覆盖正向、边界、异常，以及适用的重试、幂等场景；不要求每个用例凑齐全部分类。

**保留已有测试覆盖的有效行为。** 需求变更或测试重复时，可调整、合并或删除相关用例，并说明依据；禁止为通过测试而删除有效用例、弱化断言或改写契约。

### 2. 依赖隔离与 Mock

**UT 隔离真实外部服务与数据库**，不产生真实外部副作用；纯函数可以直接测试。测试设计须声明隔离边界，真实依赖协作属于 **[集成测试](../testing/integration-test.md)**，不能以 Mock 结果证明真实链路通过。

**项目替身方式**：{{已确定的工具、使用约定及生成入口}}。固定一种项目做法，不在每个用例中重新选型；仅检查契约要求的参数、次数或顺序，不绑定无关实现细节。

时间、随机数及外部状态应可控；用例不共享可变状态、不依赖运行顺序。并发测试隔离共享资源，临时资源由测试框架创建并清理，不硬编码真实凭据或机器路径。

### 2. 失败定位与复验

| 现象 | 核对重点 |
|---|---|
| 无法启动或大量用例失败 | 工具版本、依赖、配置与原始错误；不先重装所有依赖 |
| 行为断言失败 | 独立预期与实际行为，区分实现错误和需求变化 |
| 替身调用不匹配 | 接口、生成结果、调用条件与必要预期；不盲目放宽匹配 |
| 偶发失败 | 共享状态、时间、随机性、并发及清理责任 |

先定位具体失败，再修正并重跑受影响测试；无法解释的失败不得靠跳过用例变绿。首次失败及复验结果保留在当前 **04-verify.md**。

### 3. 覆盖率、结果与 CI

**通过标准**统一见 **[verification.md](../verification.md)** 及项目明确约定。关注本次范围和有效断言，不用全仓平均覆盖率掩盖缺口。

**CRAP** 使用当前源码、当前范围且 UT 成功后的有效覆盖数据。**变异测试（Mutation Testing）**读取逐项结果，不能只看退出码或总分。

检查失败须保留失败状态，不能被后续输出命令掩盖。终端保留关键输出，任务结果写入 **04-verify.md**；覆盖文件等工具产物按需使用，不额外要求报告文档。

**本地与持续集成（Continuous Integration，CI）**使用一致的工具、配置与验证口径；本地可运行受影响用例，交付仍须完成必要检查。项目已有 CI 门禁继续执行；未接入 CI 不编造流水线或通过记录，必要检查失败阻止后续交付。
