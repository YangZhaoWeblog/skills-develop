# API 设计规范

> 沿用项目已有协议、框架与接口约定；新项目按实际技术栈填写。HTTP、gRPC 等规则仅用于对应协议。

## 1. 协议与契约

新增或修改接口时，先更新实际 **Proto / IDL / OpenAPI / 路由定义及注释**，再按项目命令生成代码。设计约定变化时才修改本规范。

当前契约与实现入口见 **[接口契约索引](index.md)**；字段含义、单位、约束和默认值由契约维护，不复制字段表。调用方式仍不清楚时，补充示例或跨接口流程说明。

字段或接口语义变化时，追加 **[变更历史](change-history.md)**。代码生成入口见 **[local-dev.md](../runtime/local-dev.md)**；框架分层与依赖注入见 **[coding-style.md](../coding-style.md)**。

## 2. 命名与字段

**命名**沿用协议和项目约定。HTTP 路径按资源或业务动作组织，正确使用方法语义；JSON 字段保持一致的命名风格。gRPC 的 service、method、message 和 enum 按 Proto 约定定义。

**约束**写入契约及项目实际校验机制。Go 的 json、form、path、validate 等标签按字段用途使用，不要求所有字段都有全部标签。

| 字段 | 设计要求 |
|---|---|
| 时间 | 明确格式、时区和精度；沿用项目的 ISO 8601、时间戳或协议类型 |
| ID / 大整数 | 核对调用方精度；JSON 面向 JavaScript 时，超出安全整数范围的值用字符串等无损表示 |
| 金额 | 明确币种、单位与精度，采用项目约定的精确表示 |
| 枚举 / 布尔 | 使用协议支持的类型；明确未知枚举、未填写与默认值的含义 |
| 分页 | 明确游标或页码方式、排序、默认数量和上限 |

## 3. 响应与错误码

**响应结构沿用项目或框架约定**，不强制包装为 code / message / data，也不统一要求业务错误返回 HTTP 200。HTTP 状态码、gRPC Status 与业务错误之间的映射保持一致，并在项目契约或错误定义中说明。

调用方通过 **稳定的错误码或错误类型** 判断失败，不解析错误文案。错误定义集中维护；对外响应不得泄露堆栈、SQL、内部路径或凭据。面向用户的提示与诊断信息按项目约定区分。

**Trace ID 必须在调用链中传递并与日志关联。** 使用项目已有追踪上下文、HTTP Header 或 RPC Metadata；不强制在响应正文增加字段。客户端排查入口沿用项目约定。

## 4. 安全与访问控制

接口安全按实际入口启用；输入校验、密钥、加密和传输安全见 **[coding-style.md](../coding-style.md) §4**。

### 4.1 鉴权与权限

新增接口默认鉴权；公开接口明确登记。涉及操作权限、数据归属或租户隔离时逐项校验，不能只判断“已登录”。

采用 Session / Token 登录时，按认证方案处理凭据更新、过期和退出失效。使用 Cookie 时，按用途配置 **HttpOnly、Secure、SameSite** 与有效期。

### 4.2 浏览器入口

**CORS** 按实际调用方配置来源、方法和请求头；携带凭据时只允许明确的可信来源，不使用通配来源。

HTTP 服务按内容和部署方式配置安全响应头：内容类型保护用 **X-Content-Type-Options**，页面嵌入限制用 **X-Frame-Options** 或 **CSP frame-ancestors**；HTTPS 站点评估 **HSTS**，HTML 页面配置 **CSP**。不把页面规则套到纯 RPC 服务。

### 4.3 外部请求与解析

**SSRF**：目标地址可受外部输入影响时，限制协议和目标范围；校验解析后的地址与重定向目标，覆盖 IPv4、IPv6、回环、内网和云元数据地址，避免解析与连接之间绕过校验。合法内部服务走项目明确允许的入口，不开放任意目标访问。

**XML / 反序列化**：处理不可信 XML 时禁用 DTD 与外部实体；禁止将不可信数据反序列化为可执行的任意对象。

### 4.4 限流

公网入口配置限流粒度与阈值；登录、注册、改密、支付等关键操作单独评估。记录项目已有网关或服务配置入口，不重复维护另一套配置。

## 5. 兼容与版本

根据实际协议、序列化方式和调用方检查兼容性，不能仅凭“新增字段”认定兼容。Proto 字段编号不得随意更改或复用；删除字段时按协议保留编号及名称。

破坏性变化须确定兼容方案、调用方适配和发布顺序；需要新版本时沿用项目版本机制。弃用时标记 **Deprecated**，通知调用方并核对迁移情况后下线；保留周期由项目确定。

本次 **Plan** 记录受影响调用方及验证方式，**Verify** 核对执行结果。已有契约测试按项目入口运行，不为所有项目强制引入同一种框架。

## 6. 超时与批量限制

优先使用项目已有值。新项目尚无约定时，可采用以下初始值，并根据调用链和实际负载调整：普通请求 **3 秒**，批量请求 **10 秒**，分页和批量数量上限 **100**。

调用外部服务应传递超时与取消信号。大结果集按业务需要采用分页、游标或流式传输；明确数量与响应大小边界，避免无界返回。

延迟目标由项目确定，并写明测量环境与负载；不把模板示例当作已达到的性能指标。
