## 1. 项目约定与工具

核对已有规则、配置与实际代码，保留有效约定，不把历史写法自动当作规范。发现冲突或坏写法时，说明问题与改进建议，按授权更新规则。缺少规范时，引用实际语言与框架的适用规范，形成可执行的项目约定；未确定的工具和配置标明待接入。

**格式化与 Import**交给项目固定工具，缩进、分组及排序沿用语言与项目配置。不设通用行长、文件或函数行数限制，不按个人偏好强制折行。

## 2. 命名与注释

### 2.1 命名与语言约定

名称表达职责，业务含义明确的值使用有名称的常量。保留通用缩写，避免含义模糊的名称；不因已有包名含 util 或 common 就重构项目。

以下是默认约定，生成项目文档时只保留实际语言，已有配置优先：

| 语言 | 命名与 Import 默认约定 |
|---|---|
| **Go** | 包名简短小写；文件 snake_case；导出名 PascalCase、非导出名 camelCase；接收器命名一致；ID、URL 等缩写保持一致。Import 用项目 goimports 等工具整理；点导入或副作用导入须有明确用途 |
| **JavaScript / TypeScript** | 变量、函数 camelCase，类型与类 PascalCase；文件名、模块解析与导入顺序沿用项目配置；不通用禁止相对导入 |
| **Python** | 模块、函数和变量 snake_case，类 PascalCase，常量大写；下划线按 Python 语义及项目约定使用；Import 用实际工具整理 |
| **Java / C++ 等** | 沿用项目语言规范与格式工具，记录需要补充的命名、可见性及 Import 约定 |

### 2.2 文档注释

导出符号须有文档注释，说明用途、参数约束、返回及必要异常语义；使用语言对应格式。Go 注释以符号名开头，其他语言沿用项目文档工具。不保留无用途的注释代码；确需暂留时注明原因和清理条件。

### 中文步骤分块（强制）

新增或修改的手写函数，编号只用于函数顶层的主要处理阶段，使用中文和单层编号 `1. 2. 3.`。主要阶段之间留空行，同一处理组保持连续；缩进和格式沿用项目 formatter。

嵌套回调、闭包及局部方法不另起编号，默认不写注释；必要时补简短的无编号说明。测试主体单独编号，只有一个处理阶段时可保留 `1.`。注释说明阶段目的或必要约束，不逐句解释代码；修改逻辑时同步注释。

生成代码不手改，未触及的旧函数不批量补写。函数外文档注释不加步骤编号。Coder 编写，独立 Reviewer 核对分块和语义；不新增 Verify 命令或正则检查。

### 2.3 可读性与接口设计

- **深模块（Deep Modules）**：以简单接口提供完整能力，将复杂处理集中在模块内部。接口负担包括参数、配置、调用顺序、错误及使用约束；按调用方必须理解什么判断，不以形参数量或实现行数衡量。
- **删除检验**：假设删掉模块，复杂度会消失，还是分散回调用方？检查它是否集中承担实际职责，而非仅增加转发层。
- **改善阅读**：类型定义、判断条件或嵌套代码难读时，可以提取命名类型、变量或函数，让主要处理步骤更清楚。
- **避免机械拆分**：参数多、条件多或复杂度超标时，先找原因，再选择合适的处理方式，例如简化接口、合并重复逻辑、用早返回减少嵌套或按职责拆分等。不要只把代码搬进另一个函数，让数字变小、阅读却需要来回跳转。
- **输入校验**：按需求、接口契约和安全规则，拒绝不符合要求的输入。
- **新增限制**：增加校验条件前，说明要防止什么具体问题，并给出需求、契约或安全依据。

参数数量、复杂度等由项目已接入的适用工具检查；工具未覆盖的语义由 Coder 自检和独立 Reviewer 核对。分块与注释沿用上方规范，不以工具通过代替可读性审阅。

## 3. 错误、资源与并发

### 3.1 错误处理

错误须处理、传播或明确说明忽略理由，保留定位所需上下文；不得向调用方泄露敏感内部信息。遵循语言的错误或异常机制，不用进程退出掩盖可恢复错误。

- **Go**：error 放最后返回；需要保留错误链时用 **fmt.Errorf(... %w ...)**。英文错误消息通常小写开头、不加末尾标点。业务错误正常返回，panic 不用于普通业务失败。
- **JS/TS、Python、Java**：按项目异常模型捕获和传播，处理异步失败；宽泛捕获仅用于明确的边界，不能吞掉错误。

### 3.2 资源生命周期

成功获取资源后安排释放，覆盖成功、异常和提前返回路径。Go 用 defer，Python 用 with，Java 用 try-with-resources，C++ 优先 RAII；其他语言沿用对应机制。

Go 循环中使用 defer 时核对释放时机，避免把每轮资源积压到函数结束。明确文件、连接、锁和其他资源的所有者，不重复释放或遗漏释放。

### 3.3 并发与数据语义

共享可变状态须有同步或隔离；明确锁顺序，以及线程、协程、异步任务的退出和取消方式。Go 不得无保护地并发写 map 或重复关闭 channel；闭包捕获按项目语言版本核对，不套过时规则。

空值与空集合按接口语义选择；浮点比较按计算误差与业务精度确定，不统一禁止相等比较。预分配、字符串构建和指针选择以语义、语言惯例及性能证据为依据，不为模板做无关优化。

## 4. 安全编码

### 4.1 外部输入与操作边界

- **输入校验**：验证外部输入的类型、长度、范围和格式；动态标识符采用受控映射或允许列表。
- **SQL**：值使用参数化查询；不得将不可信输入直接拼接进 SQL。
- **命令执行**：使用结构化参数 API；禁止拼接不可信输入到 Shell，并核对命令参数本身的含义。
- **文件路径**：操作应受限目录时，使用适合平台和运行时的目录边界机制，考虑符号链接及竞态；仅 Clean 或字符串前缀比较不能证明安全。
- **输出**：按 HTML、属性、URL 等具体上下文编码；需要允许富文本时使用成熟清洗工具，不把清洗与转义混为一谈。

接口鉴权、CORS、SSRF 等默认规则见 **[api-standards.md](contracts/api-standards.md)**，本文件不重复维护。

### 4.2 凭据、密码与随机数

禁止把真实密钥、密码和 Token 硬编码或提交到仓库；使用项目已有凭据配置方式。日志敏感信息处理统一见 **[logging.md](logging.md)**。

**密码**使用带盐、可调成本的密码哈希方案（如 bcrypt、scrypt、Argon2id），不使用普通摘要替代。**摘要、加密与签名**用途不同；采用标准库或成熟安全库，不自制算法。SHA-2 是摘要算法，不是加密算法；敏感数据加密采用项目确认的安全方案，如 AES-GCM。

新安全用途不采用已失效的 DES、3DES、MD5、SHA-1 或 RC4。密钥、Token 等安全随机数使用 **密码学安全随机数生成器（CSPRNG）**；Go 使用 crypto/rand，不能用 math/rand 替代。

### 4.3 传输安全

敏感数据传输使用 **TLS**，最低 1.2、优先 1.3；验证证书和主机名。不得为解决连接失败直接关闭校验；隔离测试中的例外须明确批准、限定范围并防止进入生产配置。

## 5. 检查与例外

**确定性工具优先**：执行 §1 的项目检查入口，保留真实失败状态；工具缺失与检查失败分开报告，不因缺工具宣称通过。记录与复验按 **[verification.md](verification.md)**，独立审查按 **[code-review.md](code-review.md)**。

**例外先批准**：说明具体规则、理由、影响及缓解方式。获准后按需添加限定范围的 lint 抑制及说明，在当前任务或 PR 记录决定，由独立 Reviewer 核对；不能只加 nolint 就自行放行。

## 6. 正反例

示例省略依赖定义，只比较注明的问题；生成项目文档时可换成项目语言。同类例子合并或替换，注明适用条件与改善点。

### 6.1 处理分块

**反例：校验与提交挤在同一块。**

```go
func submitOrder(order Order) error {
    // 1. 处理订单。
    if err := validateOrder(order); err != nil {
        return err
    }
    return persistOrder(order)
}
```

**正例：按处理阶段分块，块间留空行。**

```go
func submitOrder(order Order) error {
    // 1. 校验订单，确认允许提交。
    if err := validateOrder(order); err != nil {
        return err
    }

    // 2. 保存订单与库存变更。
    return persistOrder(order)
}
```

### 6.3 回调编号

**反例：嵌套回调反复从 `1.` 开始。**

```typescript
function watch(child: ChildProcess, session: Session) {
  // 1. 监听进程。
  child.once("error", () => {
    // 1. 结束会话。
    session.close(new Error("CLI process failed"));
  });
  child.once("close", () => {
    // 1. 结束会话。
    session.close(new Error("CLI process exited"));
  });
}
```

**正例：外层阶段编号，同组连续，回调只补必要说明。**

```typescript
function watch(child: ChildProcess, session: Session) {
  // 1. 监听进程失败与退出，结束协议会话。
  child.once("error", () => {
    session.close(new Error("CLI process failed"));
  });
  child.once("close", () => {
    // 进程退出不代表模型成功完成。
    session.close(new Error("CLI process exited"));
  });
}
```
