# 澄清与独立核验

> **用途**：产品讨论读 §1，开发 Clarify 读 §2。产品确认不能代替开发独立核验。
>
> **提问方式**：先读取能查明的事实，再问缺失的决定。独立问题可批量问，有依赖的问题分轮问；说明依据、影响与建议，不机械限制问题数量或轮数。

讨论或核验行为时，按 **[产品现状总览](product-state/product-map.md)** 选读本次相关规则，不预读全部文档，也不把长期规则整篇复制进本轮验收条件（**Acceptance Criteria，AC**）。

## 1. 产品阶段：把想法变成可确认的需求

### 1.1 读取入口

从本轮产品 **00-overview.md** 定位当前阶段与资料来源。想法或外部资料按 **01-requirements.md** 和 **02-acceptance-criteria.md** 整理，保留原意和约束；缺口、冲突交用户确认。

外部链接只在产品 Overview 维护。来源对应方式按产品模板填写；修改外部原文须另获授权。开发以当前已确认的产品文档为准。

### 1.2 讨论与确认

| 阶段 | 要解决的问题 | 完成条件 |
|---|---|---|
| **Clarify** | 明确使用者、场景、实际困难与本轮目标；检查提出的解法是否必要 | 用户确认问题及希望改善的结果 |
| **Design** | 提出可行方案，比较依据与代价；必要时用原型取得反馈 | 用户选定方案，影响选择的关键疑问已解决 |
| **Confirm** | 核对范围、AC 及必要依据，逐项检查行为与边界 | 用户确认需求与 AC，无影响目标或验收成立的待定项 |

**原型**按 **01-requirements.md §2「方案比较与原型」** 选择和记录。AC 依赖原型时，先确认对应页面或状态，再确认 AC；原型不能代替明确的行为与预期结果。

**行为场景**经 **02-acceptance-criteria.md** 的链接读取 **acceptance.feature**，使用稳定的本地 AC 编号；Gherkin 编写与来源标注遵循产品模板，不另抄同义场景表。

产品三阶段完成后，可以结束产品会话，不要求立即开始开发。

### 1.3 变更处理

新想法不自动加入本轮；不影响当前目标时记为后续候选，影响目标成立时先讨论并确认范围调整。

同一需求的变更直接更新当前 **01-requirements.md、02-acceptance-criteria.md** 及对应场景。比较增删改，检查对开发任务、Plan 和测试的影响，修正并重新核验受影响部分；已结束的开发任务记录保留。

变化影响原确认结论且尚未获批时，将产品 Overview 的 **Confirm** 标为待确认，暂停受影响的后续工作。已明确批准的修改不重复询问。

## 2. 开发 Clarify：独立核验当前任务

### 2.1 读取入口

按 **AGENTS.md** 的恢复规则定位任务。从当前开发 **00-overview.md §3「需求与验收入口」** 读取本轮产品 **01-requirements.md、02-acceptance-criteria.md**，再按需读取相关契约、长期规则与受影响代码。

外部资料沿产品文档中的链接追溯，不在开发文档重复维护外部入口。核验结果写入当前 **01-clarify.md**，只记录结论、依据与产品条目链接，不复制完整 AC。

### 2.2 核验内容

1. **目标与范围**：需求和 AC 是否明确？已有产品确认仍须独立核验。
2. **实现与验证条件**：结合代码、契约和必要环境，是否可实现、可验证？界面 AC 的原型依据是否齐备？
3. **硬阻塞**：是否存在影响本轮成立的矛盾、遗漏或未授权副作用？不穷尽未来设计。
4. **任务拆分**：默认一个开发任务。确需拆分时，在产品 **00-overview.md §4「开发任务清单」** 列出范围、AC 对应与依赖；用户确认后建立可独立计划、实现、验证和提交评审的子任务，只细化当前 Plan，不提前写完全部子 Plan。

### 2.3 阻塞与结束条件

发现硬阻塞时，在当前 **01-clarify.md** 记录问题、依据、产品原文位置及待决定事项，停止后续开发。需要修正需求或 AC 时，说明：

> AC 核验未通过，暂不进入后续开发。原因：{{具体问题及影响}}。请先修正对应产品文档；确认变更后重新核验，通过后继续。

开发会话不自行更改产品决定，也不要求用户切换身份或新建会话。

全部已发现阻塞解决后，记录 **“无硬阻塞”**，进入当前 **02-plan.md**。实现中发现需求或 AC 问题时，仍须停止后续开发并处理问题，记录依据并区分前置核验遗漏、新获得事实与外部变化。
