# Agent 职责与派发

主控派发、子 Agent 执行时读取。阶段与授权见 **AGENTS.md**；检查标准见 **.harness/docs/verification.md**。

## 1. 分工

**主控使用强模型**，负责 Clarify、Plan、任务状态、范围判断和用户沟通。以下角色独立执行：

| 角色 | 模型档位 | 职责与交付 |
|---|---|---|
| **Coder** | 经济模型 | 按批准 Plan 实现与补测；报告改动、执行结果、偏差和阻塞 |
| **Verifier** | 强模型 | 执行所选检查；报告失败位置、证据和复验范围 |
| **Reviewer** | 强模型 | 核对需求、设计、代码、文档及验证充分性；报告问题和结论 |
| **Executor** | 经济模型 | 更新指定文档、运行固定工具、执行获准 Submit；报告实际结果 |

使用项目已核实的模型；复杂任务或持续失败时，主控调整拆分或模型。

## 2. 派发与返工

每次派发给出 **目标、任务入口、必读依据、可改范围、授权和结束条件**。Agent 读取原文与实际变更，不只依赖主控摘要；交付结论与证据位置，不搬回全部过程。同一文件不并发写入。

**Coder、Verifier、Reviewer 使用独立上下文**；验证与审查不继承 Coder 完整对话。默认一个 Verifier；仅在检查可独立执行且拆分有收益时增加，不默认嵌套派发。

1. **实现与验证**：Coder 交付，Verifier 检查。Verifier 可写临时产物与验证记录，不改实现、测试断言、AC 或门槛。
2. **批量修正**：Verifier 汇总一轮问题；主控核对依据与授权，必要时先更新 Plan，再交 Coder 修正；Verifier 复验新版本。
3. **文档与审查**：验证稳定后，Executor 更新文档，Reviewer 独立审查；不默认重跑全部工具。修改后补做受影响检查并更新文档。
4. **提交**：用户验收并授权后，Executor 执行指定 Submit 操作，核对暂存范围与 Git／平台结果；主控报告交付结论。

范围内返工不重复询问。需要用户决定的阻塞立即报告；越界修改、合入和发布须另获授权。独立审查不替代用户最终验收或项目人工审批；缺少独立执行能力时报告缺口，不以主控自检代替。
