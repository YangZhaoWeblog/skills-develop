# 编码规范生成指导

> 生成或更新 **.harness/docs/coding-style.md** 时读取；以对应模板的五节结构填写。

## 1. 读取项目事实

核对实际语言、依赖、代码目录、已有规范及格式化/lint/安全配置。Go、JS/TS、Python 按需读取对应 **language-profiles/**，其他语言沿用项目已有工具，不强套 Go。

检查实际 **core.hooksPath、Hook 配置和 CI**，确认命令是否真的被调用。工具存在或文档有命令不代表门禁已启用。

## 2. 按骨架填写

- **项目约定与工具**：已有项目沿用真实约定；新项目保留适用默认规则，未知事实标待接入。登记版本、工作目录、完整命令、配置与实际触发入口。
- **命名与注释**：只保留实际语言；中文编号分块强制要求和示例保留，示例可换成项目语言，不能恢复“只解释 Why”。旧项目约定冲突先确认。
- **错误、资源与并发**：按语言与版本适配，保留错误传播、资源释放与共享状态保护；不凭模板强制重构现有代码。
- **安全编码**：保留输入、操作边界、凭据、密码、安全随机数及传输保护；日志具体要求引用 logging.md，接口默认规范引用 api-standards.md。
- **检查与例外**：工具检查与独立审查分工明确；未知或失败不写通过，豁免需明确授权。

复杂度等门槛引用 **verification.md**；参数超过5只作审阅提示，不增加参数数量检查器。无通用行长、函数或文件行数门槛。已有项目格式配置保留，冲突先确认。

覆盖率、CRAP、变异命令维护在 **testing/unit-tests.md**，本文不重复维护。没有自动检查器的语义规则由 Review 核对，不把文字规范描述成已自动执行。

## 3. 适配与核对

确认使用相应框架后才读框架参考，按实际能力应用。已有权威规则只维护一份，保留必要摘要与链接；融合边界按 **[upgrade-project.md](upgrade-project.md)**，不得静默覆盖项目规则或历史。

核对命令、章节引用及适用语言，Source / 核对时间只记录真实核验。纯文档或未定技术栈项目保留适用骨架，缺口明确，不编造工具或代码规范。
