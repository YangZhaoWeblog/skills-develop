# go-zero 项目适配

> 仅在依赖和代码确认使用 **go-zero** 时读取；普通 Go 项目不加载。

## 1. 分层与依赖

核对项目实际目录、入口、ServiceContext、配置加载与错误处理方式。保留已有分层和依赖注入边界，不强制新增 handler、model、errorx 等项目未采用的结构或工具。

## 2. 协议与生成

有 **.api** 时记录其定义、路由及实际生成命令；有 **.proto** 时记录 RPC 定义及生成入口。纯 RPC 项目不引入 HTTP 路由、URL 版本或 JWT；鉴权按项目已采用的机制填写。

生成文件与源文件的关系须明确；命令引用 Makefile 或已有工具入口，不另建一套执行方式。

## 3. 测试与运行

根据本次行为选择被测层和隔离边界，复用项目现有测试框架。集成测试沿用最小入口；未接入时不因使用 go-zero 而安装 testcontainers 或创建环境。

只登记实际使用的 etcd、Redis、数据库及其他依赖。启动、配置和服务发现说明来自代码及配置，不从框架名称推断。
