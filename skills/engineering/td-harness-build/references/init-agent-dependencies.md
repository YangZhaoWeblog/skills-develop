# 上下游与集成关系生成指导

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主控指定的输入、文件范围和授权处理本专题。

> 填写 **.harness/docs/dependencies.md** 时读取。模板为 **[dependencies.md](../assets/project/docs/dependencies.md)**，与 Architecture 分别维护外部集成明细和系统整体结构。

## 1. 核对真实集成

读取项目实际语言的公开入口、调用代码、依赖与锁文件、协议、配置及集成资料。路由注册只证明提供某个入口，不能据此编造调用方；依赖声明也不证明实际调用。

识别服务、库、CLI、插件宿主、SDK、消息等实际交互。上下游按调用和数据方向说明，双向交互写清各自用途；不强套 HTTP 服务结构，不抄全量包依赖。

## 2. 按四节填写

- **上游清单**：对象、用途、方式、本项目入口及仓库 / 资料；未知调用方如实标注，不强填联系人。
- **下游清单**：关键依赖、用途、方式、集成代码及资料入口；具体约束写入契约说明，失败处理只在 §4 维护。
- **契约与调用**：说明跨系统交互及必要兼容约束，链接实际协议和配置；不复制字段或参数表，不重复 Architecture 的内部调用链。
- **故障影响**：从实际实现核对超时、重试、降级、错误及数据影响，没有依据时标待核实，不把建议写成现状。

已有复杂流程用链接复用，确需单独说明集成交互时按需配图。暂无外部关系时保留简短说明，不凑对象或虚构服务承诺。

## 3. 迁移与验证

已有 **.harness/docs/dependency-map.md、.harness/dependency-map.md、harness/dependency-map.md** 时，先完整读取，保留清单、图、故障分析及独有项目信息；按 **[upgrade-project.md](upgrade-project.md)** 融合并修复引用。内容保留且删除已获授权后，才移除旧入口；未完成报告待迁移，不生成第二份同义关系文档。

核对清单、契约、故障记录与真实代码一致，所有入口可定位；图与 Architecture 不冲突。Source / Last-verified 仅记录实际核验，报告缺口及未确认项，不把推断冒充已验证事实。
