# API 契约梳理指令

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主控指定的输入、文件范围和授权处理本专题。

负责 `.harness/docs/contracts/` 的契约索引、变更历史和必要的调用说明。

## 1. 核对真实契约

先检查 proto / IDL 生成配置、生成代码来源和服务注册，或项目实际路由及接口定义。排除 vendor、第三方依赖和示例；仅发现 `.proto` 文件不能证明它是本项目契约。

- proto 项目引用真实 `.proto` 路径、service、message 和注释。
- 其他项目引用真实 IDL、类型定义或路由，不为统一格式另造字段表。
- 无对外接口时跳过生成；已有人工文档或历史记录保留，不自动删除目录。

## 2. 检查说明是否够用

新增或修改接口时，检查调用者能否根据契约正确使用：字段含义、单位 / 格式、取值约束、必填条件、缺省 / 空值语义及必要的跨字段关系。

字段说明由实际契约的注释或描述维护，并核对实现；不要把猜测写成契约。文档初始化发现缺口时，报告契约位置与依据，由主控按授权安排修正，不直接修改契约。不要求一次补齐所有历史注释；后续 Docs 核对本次已获准的契约变更及受影响说明。

只索引当前契约，不生成逐接口字段说明 Markdown。跨接口业务流程、调用示例或无法在契约中清楚表达的行为，按需写补充文档并引用契约；已有人工文档保留；本次变更影响的说明须同步更新，无关历史文档不逐篇更新。

## 3. 保留变更历史

`contracts/change-history.md` 集中记录接口与字段演进，按其记录规则追加日期 / 版本、接口 / message、字段路径与编号、变更前后、原因、兼容性影响和依据。

- 旧字段表模板不再生成；清理已有旧文件须按升级确认执行，先保留人工内容及历史。
- 不删除已有字段 / 接口变更历史；迁移旧接口文档时原样保留变更内容和可追溯出处。
- 不从当前实现反推未知的旧行为或日期，未确认项标“待核对”。
- 不把历史表当成当前字段定义，不重复保存完整字段说明表。

## 4. 回写索引

`contracts/index.md` 记录模块职责、真实契约路径、service / 方法或路由、实现位置及核对时间，链接历史表及必要的补充说明。`api-standards.md` 保留项目协议、路径和版本约定。

**响应与错误模型沿用项目或框架现状**，不因生成 Harness 改写接口包装、状态码或错误结构。按实际机制记录 **Trace ID** 的传递与日志关联方式，不强制增加响应字段。新项目缺少约定时列为待确认；超时等初始值按规范填写，不能当作运行事实。

项目契约清单填写在索引的项目自定义区，项目特定约定填写在规范的项目自定义区；已有内容按升级规则保护。

升级按 [upgrade-project.md](upgrade-project.md) 保留项目内容；已有无明确边界的文档先列为 MERGE 并取得授权。只处理本次授权范围，不修改无关源码、文档或历史记录。
