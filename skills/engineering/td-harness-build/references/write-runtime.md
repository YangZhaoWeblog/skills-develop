# 环境与发布文档填写指导

初始化、升级或本次环境与发布方式变化时读取。负责 **.harness/docs/runtime/**，不为填写文档搭建环境。

## 1. 核对项目事实

读取项目已有 README、依赖与锁文件、构建脚本、配置和 CI/CD 定义。仅在项目实际使用时读取容器、集群或环境工具配置；不预设语言、操作系统或部署平台。

命令与版本必须有依据。已有项目直接整理已知事实；空项目或缺少信息时标明缺口，需要作出技术选择时再由用户决定。

## 2. 按固定模板填写

| 文件 | 职责 |
|---|---|
| **local-dev.md** | 本地安装、配置、运行与调试；链接交付入口 |
| **release.md** | 发布方式、发布检查与失败恢复 |

复制模板，保留标题和表头，在项目自定义区填写。行数按实际操作增减，额外事项放“项目补充”；长命令放表后代码块，表内定位。已有文档中的独有内容须保留，不为符合骨架删掉有效信息。

**有能力就填入口，没有就说明。** 未建立写“未接入”，不适用写“不适用”，无法确认写“待确认”。必要验证缺少环境时，按当前 Plan 记录并解决缺口。

发布操作在 **release.md** 维护。日志规则与查询入口只在 **logging.md** 维护，测试命令引用对应测试规范。

尚无发布方式时，**release.md** 仅注明“尚未建立发布方式”，其余保留骨架；准备交付版本时再填，已有发布方式则按现状整理。

## 3. 核对执行情况

命令注明来源与验证情况。仅实际执行成功后才能标为已验证，并记录时间；未执行写明原因。执行前核对权限与副作用，缺少授权的安装、启动、发布或数据操作不因填写文档自动执行。

不添加项目尚未采用的 CI/CD、容器、集群或测试平台。后续建立这些能力时，在 **Docs** 阶段更新相应章节。

## 4. 升级保留

按 **[upgrade-project.md](upgrade-project.md)** 保留已有项目内容。旧版环境文档可能把真实命令填在模板边界上方，因此已有环境文档均须检查实际内容，列入已授权的合并范围后更新，不能按旧边界机械覆盖。

脚本只补缺，已有文件保持原样；模板复制成功不代表命令或环境已经验证。
