# AGENTS 生成与审查

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主控指定的输入、文件范围和授权处理本专题。

> 生成或融合项目 AGENTS 时读取。模板为 `assets/agents.md`，修改边界见 [upgrade-project.md](upgrade-project.md)。

## 1. 保留结构与规则

`build_harness.sh` 仅在入口缺失时复制模板。入口初始化 Agent 完整读取已有入口，按授权融合，由主控核对；项目内容、工具约定和未解决冲突必须保留。只有只读权限时，返回候选与依据，由主控写入。

保留模板的产品三步、开发七步、恢复与读取边界、确认和停止条件。产品与开发阶段表统一使用“#、步骤、产物、说明”四列。“步骤”列的阶段名称加粗。Workflow 依次为 2.1 总体工作流程、2.2 产品工作流、2.3 开发工作流、2.4 目录与职责、2.5 创建与恢复、2.6 用户确认；确认点写入对应阶段，操作细节由阶段模板或专题规范维护。项目流程冲突交用户决定，不能靠压缩文字删除授权或证据要求。

## 2. 按证据填充

| 位置 | 内容与依据 |
|---|---|
| 顶部项目 / Stack | 一句话用途及主要语言、框架；读取 README、已有入口及依赖配置 |
| Commands | 模块或包名、启动入口及构建、测试、生成命令；引用详细规范，缺失明确标记 |
| Structure | 关键目录职责、分层方向、生成代码边界；读取目录和调用关系 |
| Rules | 保留项目命名、数据访问、契约、迁移、注释、错误处理及保护分支等适用约束 |
| 主题索引 | 按下方必做步骤核对主题、实际文件和读取时机 |

仓库类型仅在影响操作时写入 Structure，例如多项目目录与工作目录。AI 有特殊职责时写入 Rules；“高级开发工程师”等通用角色不写。详细版本维护在项目配置和环境规范，必要的版本约束保留在 Rules。

模板骨架必须保留，必填事实未知时标明待定或不涉及，不编造内容。可选信息无实际作用时省略。项目语言不限于 Go；按真实技术栈采集。

### 主题索引填充（必做）

1. 用 `rg --files --hidden` 定位项目文档、契约和工具配置；读取已有索引，保留有效的项目入口。
2. 逐行核对模板主题，替换为项目实际路径。接口契约补实际 proto / IDL / OpenAPI / 路由入口；数据库和运维文档按项目位置填写，不照抄示例路径。
3. 核对项目已有的 hook、CI、工作流门禁、Harness 治理和测试专属规则。存在时补对应主题及真实文件或配置入口；规则权威与冲突处理留在专题规范，不塞进索引。
4. 检查每个入口是否存在、主题是否覆盖。不存在且不适用的条目移除；必要资料缺失时标明“待补齐”并报告，不能写成可用链接。不得仅为凑齐索引创建治理文件。

索引固定为“何时读取、主题、文件”三列。主题全部加粗，“何时读取”使用普通文本。每个主题有明确入口；低频子文档由主题索引链接。实际路径核对完成前，不能把模板复制报告为索引接入完成。

## 3. 核对

- 对照旧入口逐条核对项目规则，独有内容已合并或列明冲突；不能以模板缺项为由丢弃。
- 实现授权、任务隔离、测试先行、真实证据及 Git 边界完整。
- 产品和开发的 Clarify 分工、AC 来源、AT 设计及执行位置一致。
- 主题索引逐项核对完成，实际契约、项目配置和专属规范入口已补齐；缺口明确报告。
- 所有引用可达；CI 或 hook 强制执行须有实际配置证明。
- Agent 分工入口指向 **.harness/agents.md**，本阶段核对链接与职责位置；四角色配置和实际调用由后续 **agent-setup.md** 接入，未核验前不能写“已安装”。
- 主入口保持简短；详细说明通过专题引用提供，职责和硬约束不得为凑行数而删除。

报告本次差异、核对结果及待处理项。最终验收和提交授权沿用任务流程。
