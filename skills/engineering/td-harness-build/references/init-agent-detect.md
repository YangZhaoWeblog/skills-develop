# 检查项目能力

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主 Agent 指定的输入、文件范围和授权处理本专题。

> 复制可选的接口或数据文档前读取。只读检查项目，不连接数据库，不启动服务。

## 1. 收集证据

先用 **rg --files --hidden** 查看项目文件，排除依赖、构建输出与生成缓存。按实际语言读取依赖清单、锁文件、入口、契约及结构定义；不要靠框架包名或单一文件名下结论。

| 能力 | 足够的项目证据 | 常见误判 |
|---|---|---|
| 对外 API | 项目自己的路由注册、服务实现与实际使用的契约入口 | 把 HTTP 客户端、第三方 Proto 或示例当成项目接口 |
| 数据存储 | 项目持久化用途、数据模型或 Schema、实际数据访问入口 | 把文档示例、依赖包或纯临时缓存当成数据库设计 |

非关系型存储按实际用途判断，不要求存在 SQL。仅有缓存时说明其用途以及是否需要长期数据说明；空项目以当前事实为准，未来计划不算已经接入。

## 2. 返回结果

两项均确定时，返回下面四行，路径附在证据中。主 Agent 将布尔值传给构建脚本，不重新猜测。

```text
HAS_API=true|false
HAS_DB=true|false
EVIDENCE_API=项目证据及路径；无接口时说明已核对范围
EVIDENCE_DB=项目证据及路径；无存储时说明已核对范围
```

目录不可读、关键文件缺失或证据矛盾时，返回阻塞原因，不把未知变成 false：

```text
STATUS=blocked
REASON=缺少的证据及下一步
```

解决阻塞后重新核对，再执行能力相关的复制。探测结果只决定是否需要相应文档，不代表接口、存储或测试已验证可用。
