# 库项目的文档适配

> 项目交付的是库、SDK 或可复用包时读取；其他项目不套用本页。

## 1. 明确使用者与边界

从包入口、导出接口、依赖和实际用例核对：谁调用这个库、提供哪些能力、哪些责任留给调用方。库没有服务部署、监听端口或数据库时，相关栏目写不涉及，不补造运行平台。

## 2. 按调用方式填写

README 展示安装或依赖声明、一个最小可运行用例及关键限制；版本、构建和测试细节引用 **.harness/docs/devops/local-dev.md**。接口说明直接引用实际签名、类型和文档注释，复杂使用顺序再补示例。

架构说明关注公共 API、内部模块、扩展点和资源所有者。上下游说明列实际消费者与外部依赖；无法从仓库确认的使用方标为待核实，不根据包名推断客户。

## 3. 兼容与验证

公开接口变化需核对源代码兼容、运行行为和分发方式。通过实际构建及测试验证项目支持的版本，不给未测试的平台打勾。性能、并发安全和资源释放按项目契约说明，不统一附加承诺。

没有守护进程或服务发布不影响使用开发工作流。验收依据应覆盖调用者可观察的行为，发布说明记录项目实际的包发布、版本标记或制品分发入口。
