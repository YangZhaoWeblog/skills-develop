# Code Review 规范生成

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主 Agent 指定的输入、文件范围和授权处理本专题。

> 初始化或升级 `.harness/docs/code-review.md` 时读取。先遵守 `upgrade-project.md` 的项目内容保护规则。

## 目标

此文件是 AI 与人工的唯一长期审查标准；当前任务 `06-review.md` 仅记录本次发现、处置和验收。不要重新生成另一份顶层检查清单。

## 采集与填充

- 从 Git/项目规则确认保护分支、提交策略与团队审批人数；个人项目采用独立 AI 验收加用户最终确认。
- 从 Makefile、package scripts、CI、测试与编码规范读取固定命令，不能写不存在的 target 或要求每次 Agent 自行找工具。
- 数值门槛引用 `.harness/docs/verification.md` 与项目明确覆盖值，不另写覆盖率或行数标准；未配置执行入口时明确缺口，不报已实现。
- 保留需求/AC符合性、分层、依赖、安全、并发、测试独立预期、兼容性和实际证据等适用审查项；无相关技术的项裁剪。
- 可读性与接口设计、中文步骤分块按 coding-style.md 由独立 Reviewer 核对；明确规则保持必须修正，不能因章节位置或严重度降为可选。工具结果与语义审阅分开，不把 Verify 通过当作可读性通过。旧代码重构沿用 verification.md 的审批与展示规则。
- 保留源模板 §1 的审阅方法：先独立追踪关键行为，再核对作者与工具结论；有疑点才比较替代结构，规则冲突交主 Agent。不能简化成“检查可读性”的勾选项。
- Reviewer 给出具体位置、依据、影响与建议，记录审查范围。不以个人折行偏好、代码行数或重复次数强迫抽象。

## 旧入口处理

旧 `.harness/review.md` 先完整读取，把独有的有效项目规则合并到本规范，再按升级确认表删除旧入口并更新引用；不直接丢弃项目内容。已有任务 Review 记录不删、不重编号。

## 约束

只填充本规范；命令、版本和项目规则须来自证据。例外需明确批准，工具检查失败不以忽略注释自行绕过。人工最终确认和项目要求的人工 Reviewer 不被 AI 代替。
