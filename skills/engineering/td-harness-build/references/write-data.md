# 数据库文档生成与更新

> 初始化或更新 **.harness/docs/data/database.md** 时读取；已有内容按 **[upgrade-project.md](upgrade-project.md)** 保留与融合。

## 1. 确认结构来源

按 **[能力探测](inspect-capabilities.md)** 核对持久化证据。无数据库时不填数据库文档；已有人工内容与历史保留。

识别项目用 **Migration、声明式 Schema 或 ORM 定义**管理结构，在数据库清单中记录实际路径及生成关系。缺少部署证据时标明“运行环境待核实”，不把代码定义当作线上现状。填写文档不授予数据库连接或操作权限；需要访问时先核对已有授权。

## 2. 填写说明与入口

保留模板标题和表头，在项目自定义区填写数据库用途、主要实体、关系、事务边界、迁移策略及项目约束。按实际存储增减表格行，未接入、不涉及和待确认分别说明，不为填文档新增能力。**字段、类型、默认值和索引定义直接引用权威来源**，不手工复制完整 DDL 或字段表。

迁移脚本留在项目既有目录，保留已执行历史。需要结构快照时使用项目工具生成，记录来源、命令和时间；不为填文档另建一套结构同步脚本。没有工具时保留源文件链接。

数值限制来自项目配置、约定或验证结果；没有依据时标明待确定。只给实际核验的内容填写 **Source / Last-verified**。

## 3. 核对与迁移

核对链接、说明与实际结构来源一致。旧模板边界上方也可能有项目事实，升级时保留并按授权融合，不按边界位置直接覆盖。已有人工结构文档先保留独有解释，再按 **upgrade-project.md** 处理重复定义和旧入口；不直接删除历史脚本或覆盖项目内容。
