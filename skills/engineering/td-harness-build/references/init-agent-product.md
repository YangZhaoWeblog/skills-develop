# 产品现状文档

> **独立初始化 Agent 指令**：执行前读取 [派发约定](init-agents.md#2-派发约定)，按主控指定的输入、文件范围和授权处理本专题。

初始化后填充产品文档，或 **Docs** 阶段涉及产品行为变化时读取。

## 1. 文件职责

通过已有初始化脚本，从 **assets/project/docs/product-state/** 补缺复制到 **.harness/docs/product-state/**。

| 文件 | 维护内容 |
|---|---|
| **product-map.md** | 用户、产品边界、核心能力和子文档入口 |
| **user-flows.md** | 用户操作、分支和可见结果 |
| **business-rules.md** | 业务状态、精确条件、限制及结果 |

先读 **product-map.md**，再按问题读取子文档。讨论或实现产品行为时，核对相关长期规则；不按每个功能新增文件。

**精确条件只在 business-rules.md 维护。** 流程图保留理解分支所需的简短条件，详细规则通过链接引用。技术模块、接口字段和数据结构引用对应技术文档。

## 2. 图与文字

产品全景用关系图，用户操作用流程图，业务状态用状态图，条件分支用决策树。图已表达的内容不逐段复述；精确数值、例外和限制放业务规则表。没有图形关系时直接用表。

优先使用 **Mermaid** 等可维护图源。展示界面时可用截图或 **GPT Image** 配图，标明实际界面或示意图。修改后检查渲染、文字可读性及事实一致性。

## 3. 现状依据

从实现、运行结果、测试和当前有效资料核对内容，记录 **来源与核对时间**，区分 **代码支持** 与 **运行已验证**。用户和用途不能仅凭代码推断；依据不足时标为“待核实”。

空项目保留模板，注明尚无已实现能力。未实现的需求、候选想法和规划不写为现状；历史任务出现过某项能力，也不能证明它当前存在。

本轮需求与验收条件由[产品任务模板](../assets/workflows/product/00-overview.md)维护；需要澄清时读取 [clarify.md](../assets/project/docs/clarify.md) 的产品部分。长期文档可链接验收依据，不复制任务讨论、测试步骤或历史结果。

## 4. 更新与升级

**Docs 阶段**：将本次已确认、已实现的变化写入对应文件，并检查全景图摘要及相关链接。保留已结束的任务记录。

**Harness 升级**：按 [upgrade-project.md](upgrade-project.md) 补缺和合并，保留项目自定义区；模板升级不授予重写项目内容的权限。

交付前核对链接、内容归属和事实依据。**复制成功只证明模板已生成**，不能据此声称产品现状已核实。
