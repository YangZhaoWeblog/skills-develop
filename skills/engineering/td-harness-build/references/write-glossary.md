# 术语表生成指导

> 填写 **.harness/docs/glossary.md** 时读取；收录标准与记录结构统一见 **[glossary.md](../assets/project/docs/glossary.md)**，本文件不另设标准。

## 1. 采集与核对

读取相关需求、已有术语说明、关键类型与标识符、配置及接口注释，识别影响项目理解的概念、缩写和歧义。不要按搜索结果有无决定收录，也不批量搬运行业术语。

核对词在本项目中的实际含义和依据。标准概念链接权威定义，只补项目用法或限制；定义冲突或关键含义未知时如实标待确认，不猜测、不静默丢弃。

## 2. 填写与保留

每个概念只填一条定义，缩写、全称与别名同条维护。易混概念写区别，弃用名称保留日期、替换与依据；不为合并叫法擅自修改代码或产品概念。

**每个 Harness 必须生成并保留术语表。** 没有符合条件的条目时注明“暂无”，不凑内容。已有项目定义和更名历史按 **[upgrade-project.md](upgrade-project.md)** 保护；重复项先核对语义再合并，冲突交用户确认。

## 3. 核验

检查一词多义、同义词混用、缩写全称与实际代码是否一致，入口能否定位。来源不完整时保留已知事实并报告缺口，不把未确认定义写成结论。
